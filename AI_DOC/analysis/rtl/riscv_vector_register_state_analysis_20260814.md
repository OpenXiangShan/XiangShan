# RISC-V RVV 向量寄存器与控制状态字段分析

## 1. 范围与结论

本文依据 RISC-V International 的 [Vector Extension](https://docs.riscv.org/reference/isa/v20260120/unpriv/v-st-ext.html) 中 30.1 节，说明 RVV 向量数据寄存器、向量控制状态寄存器（CSR）及其字段语义。

最容易混淆的结论是：`v0` 到 `v31` 这 32 个向量数据寄存器本身没有固定命名子字段。每个寄存器只是固定宽度为 `VLEN` 位的原始存储体；元素宽度、寄存器分组、有效元素范围及非活动元素的写回策略，由全局向量 CSR 决定。

## 2. 基础术语

| 术语 | 含义 |
| --- | --- |
| `VLEN` | 单个物理向量寄存器的固定位宽，由实现决定。`vlenb = VLEN / 8`。 |
| `ELEN` | 实现能处理的最大向量元素位宽，是硬件能力上限，不是运行时 CSR 字段。 |
| `SEW` | 当前选中的元素位宽，由 `vtype.vsew` 设置。 |
| `LMUL` | 当前一个逻辑向量操作使用的寄存器组倍率，由 `vtype.vlmul` 解码得到。 |
| `EEW` | 某个具体向量操作数实际使用的元素位宽，可由访存指令编码或 widening/narrowing 语义给出。 |
| `EMUL` | 某个具体向量操作数实际需要的寄存器组倍率，满足 `EMUL = (EEW / SEW) * LMUL`。 |
| `VLMAX` | 当前 `SEW` 和 `LMUL` 下可容纳的最大元素数：`VLMAX = LMUL * VLEN / SEW`。 |
| `vl` | 当前指令实际处理的有效元素数，满足 `0 <= vl <= VLMAX`。 |

对于 `LMUL=1`，元素从向量寄存器的低位向高位依次排列，元素 0 位于最低的 `SEW` 位。对于 `LMUL>1`，多个连续物理寄存器共同构成一个逻辑寄存器组；例如 `LMUL=2` 的 `v8` 操作数使用 `v8` 和 `v9`。

## 3. 向量数据寄存器

RVV 提供 32 个架构可见向量数据寄存器：`v0` 到 `v31`。每个寄存器有固定 `VLEN` 位状态，复位后其内容可以是任意值。

`v0` 不是独立类型的掩码寄存器。在掩码向量指令中，谓词总是从 `v0.mask[i]` 取值：该位为 1 时元素 `i` 执行，为 0 时元素 `i` 被关闭。它仍然是普通向量寄存器，只是在这个操作数位置按每元素 1 bit 解释。掩码寄存器始终只占一个物理向量寄存器，不受 `LMUL` 分组影响。

## 4. `vtype`：决定寄存器解释方式的核心 CSR

`vtype` 是 XLEN 位只读 CSR，只能由 `vsetvli`、`vsetivli` 或 `vsetvl` 更新。它的架构字段布局为：

```text
XLEN-1 | XLEN-2:8 | 7   | 6   | 5:3  | 2:0
vill   | reserved | vma | vta | vsew | vlmul
```

| 字段 | 含义 | 语义与使用注意事项 |
| --- | --- | --- |
| `vlmul[2:0]` | 向量寄存器组倍率编码 | 三位有符号指数编码，决定 `LMUL`。它影响寄存器分组和 `VLMAX`。 |
| `vsew[2:0]` | 选中元素位宽编码 | 设置动态 `SEW`，因此决定每个寄存器被分为多少个元素。 |
| `vta` | tail agnostic | 为 1 时，索引 `i >= vl` 的尾部目的元素可保留旧值或被覆写为全 1，软件不得依赖其结果；为 0 时尾部元素保持旧值。 |
| `vma` | mask agnostic | 为 1 时，被掩码关闭的目的元素可保留旧值或被覆写为全 1，软件不得依赖其结果；为 0 时这些元素保持旧值。该位不控制是否启用掩码。 |
| `vill` | vector type illegal | 上一次配置请求硬件不支持的 `vtype` 值时置位。此时依赖 `vtype` 的向量指令会触发非法指令异常。置位时其余 `vtype` 位必须为 0。 |
| `vtype[XLEN-2:8]` | 保留位 | 写入时应为 0。 |

`vta` 和 `vma` 只描述不产生新有效结果的位置如何写回，不改变哪些元素被计算。`vma` 对应的是已启用掩码的指令中、`v0.mask[i] = 0` 的元素；无掩码指令没有这类 inactive 元素。

### 4.1 `vsew` 编码

| `vsew[2:0]` | 汇编写法 | `SEW` |
| --- | --- | --- |
| `000` | `e8` | 8 bit |
| `001` | `e16` | 16 bit |
| `010` | `e32` | 32 bit |
| `011` | `e64` | 64 bit |
| `100` 到 `111` | - | 保留 |

### 4.2 `vlmul` 编码与 `LMUL`

`vlmul` 按三位补码有符号数解释，规范给出的关系为：

```text
LMUL = 2 ^ signed(vlmul[2:0])
```

| `vlmul[2:0]` | 有符号指数 | `LMUL` | 汇编写法 |
| --- | --- | --- |
| `000` | 0 | 1 | `m1` |
| `001` | 1 | 2 | `m2` |
| `010` | 2 | 4 | `m4` |
| `011` | 3 | 8 | `m8` |
| `100` | -4 | - | 保留 |
| `101` | -3 | 1/8 | `mf8` |
| `110` | -2 | 1/4 | `mf4` |
| `111` | -1 | 1/2 | `mf2` |

当 `LMUL=2/4/8` 时，组起始寄存器号必须分别按 2/4/8 对齐。例如，`LMUL=4` 时 `v8` 表示 `v8` 到 `v11` 的组，而以 `v9` 作为该组起始编号是保留用法。

### 4.3 `EEW` 与 `EMUL`：特定操作数的实际宽度和容量

`SEW` 和 `LMUL` 是当前 `vtype` 的默认配置；`EEW` 和 `EMUL` 则描述某个具体源或目的操作数。它们不是 `vtype` 中新增的字段：`EEW` 来自该操作数的指令语义，`EMUL` 是硬件和软件据此计算出的有效寄存器组倍率。

```text
EMUL = (EEW / SEW) * LMUL
```

该公式的设计原因是保持同一 `vl` 下的元素数量。当前默认配置可容纳：

```text
VLMAX = LMUL * VLEN / SEW
```

个元素。若某个操作数的元素宽度为 `EEW`，保存同样多元素所需的 bit 数为：

```text
VLMAX * EEW
= (LMUL * VLEN / SEW) * EEW
= EMUL * VLEN
```

因此，`EMUL` 表示该操作数跨越多少个单寄存器 `VLEN` 容量。普通等宽向量 ALU 指令中 `EEW=SEW`，故 `EMUL=LMUL`。只有 widening、narrowing 或带显式元素宽度的向量访存等混合位宽场景，二者才会不同。

例如，假设 `VLEN=128` 且当前配置为 `e16,m1`，则 `VLMAX=8`。widening 操作的源元素仍为 16 bit：`EEW=16`、`EMUL=1`；目的元素变为 32 bit：`EEW=32`、`EMUL=2`。目的操作数需要两个连续寄存器容量，例如以 `v8` 为目的组起始寄存器时实际覆盖 `v8,v9`，才能容纳同样 8 个结果元素。

将 `EEW` 设计为按操作数变化，而不是每遇到混合位宽就重设 `SEW`，可避免在循环中频繁执行 `vset*` 并改变当前 `vl` 配置。`EMUL` 则给出统一的寄存器映射规则，便于解码器检查寄存器对齐、确定读写覆盖范围，并由具体实现决定是否拆为多个 uop。

## 5. 其他向量 CSR

| CSR | 地址 | 关键字段或内容 | 含义 |
| --- | --- | --- | --- |
| `vstart` | `0x008` | 整个寄存器 | 下一条向量指令从哪个元素索引开始执行。异常或中断导致可恢复的向量指令暂停时，硬件可记录出错元素索引；正常完成后向量指令将其清零。 |
| `vxsat` | `0x009` | `vxsat[0]` | 定点累计饱和标志。定点结果因无法表示而饱和时置位；软件通常先清零，再检查一段计算是否发生饱和。高位应写 0。 |
| `vxrm` | `0x00A` | `vxrm[1:0]` | 定点舍入模式。高位应写 0。 |
| `vcsr` | `0x00F` | `[2:1] = vxrm[1:0]`，`[0] = vxsat` | `vxrm` 与 `vxsat` 的合并访问入口，其余位保留。 |
| `vl` | `0xC20` | 整个寄存器 | 当前有效向量长度，即应产生结果的元素数。主要由 `vset*` 指令设置，fault-only-first load 也可缩短它。 |
| `vtype` | `0xC21` | 见第 4 节 | 当前元素布局、分组和非活动元素写回策略。 |
| `vlenb` | `0xC22` | 整个寄存器 | `VLEN / 8`，单个物理向量寄存器的字节数，是实现时固定常量。 |

`vxrm[1:0]` 的编码为：`00=rnu`（最近向上）、`01=rne`（最近偶数）、`10=rdn`（向下）、`11=rod`（向奇数，也称 jam）。

## 6. `vlmul`、`LMUL` 与 `LMULs` 的关系

三者不是同一个层级的名字：

| 写法 | 是否是架构字段 | 正确含义 |
| --- | --- | --- |
| `vlmul` | 是 | `vtype[2:0]` 中实际存储的三位编码。 |
| `LMUL` | 否 | 由有符号 `vlmul` 解码出的逻辑寄存器组倍率，例如 `m1`、`m2` 或 `mf2`。 |
| `LMULs` | 否 | 英文复数，表示多个不同的 `LMUL` 取值；不是另一个 CSR 或字段。 |
| `lmuls` | 否 | RVV 规范没有这个小写字段名。若某份实现代码把它写作 `lmulS` 或 `lmuls`，它是项目内部命名，常见意图是“按有符号数解释的 `vlmul`”，必须以该代码定义为准。 |

例如，`vlmul = 3'b111` 的位模式按无符号看是 7，但规范要求按有符号三位补码解释为 -1，因此对应 `LMUL = 2^-1 = 1/2`，汇编写为 `mf2`。这正是不能把 `vlmul` 当作普通无符号倍率的原因。

## 7. 配置示例

假设实现的 `VLEN=128`，执行：

```asm
vsetvli t0, a0, e32, m2, ta, ma
```

该配置的含义为：

| 项目 | 值 |
| --- | --- |
| `vsew` / `SEW` | `010` / 32 bit |
| `vlmul` / `LMUL` | `001` / 2 |
| `VLMAX` | `2 * 128 / 32 = 8` 个元素 |
| 若硬件返回 `vl=6` | 元素 `0` 到 `5` 是有效 body 元素，`6` 到 `7` 是 tail 元素 |
| `ta` | tail 元素的目的寄存器内容不可依赖 |
| `ma` | 若指令使用 `v0.t` 掩码，被关闭元素的目的寄存器内容不可依赖 |

因此，程序只应消费 `vstart <= i < vl` 且掩码为真的元素结果。尾部、被掩码关闭的元素，以及 `vill=1` 时的向量结果，都不能作为后续计算的可靠输入。

## 8. 其他向量状态字段及其设计原理

除 `SEW`、`LMUL`、`EEW` 和 `EMUL` 外，RVV 还需要解决五类问题：一次实际处理多少元素、向量指令中断后如何续跑、哪些元素按条件执行、无需产生有效结果的位置如何写回，以及定点数值语义和操作系统上下文如何管理。

### 8.1 元素执行范围

对一次向量指令及元素索引 `i`，RVV 将元素分为以下范围：

```text
i < vstart             ：prestart，已完成，不重复执行
vstart <= i < vl       ：body，本次指令应处理的范围
  v0.mask[i] = 1       ：active，实际执行
  v0.mask[i] = 0       ：inactive，被掩码关闭
i >= vl                ：tail，超过本次有效长度
```

这个划分是 `vl`、`vstart`、掩码、`vta` 和 `vma` 的共同语义基础。它使硬件能够在同一条向量指令中同时表达循环尾部、条件执行和异常恢复，而无需将程序拆成多个标量分支。

### 8.2 `vl`：本次实际处理的元素数

`vl` 是当前有效向量长度，表示本次指令应产生有效结果的元素数；它不等于理论容量 `VLMAX`。例如当前配置可容纳 8 个元素、但循环只剩 5 个数据时，软件或硬件将 `vl` 设为 5。

设计上，`vl` 是 vector-length agnostic 编程模型的关键。程序提交剩余工作量作为 AVL，`vset*` 指令根据当前 `VLEN`、`SEW` 和 `LMUL` 返回本轮可处理的 `vl`。同一个二进制因而可运行在 `VLEN=128`、`256` 或更宽的实现上，不必为每种硬件宽度重写循环。

```text
VLMAX：当前寄存器配置可容纳的最大元素数
vl   ：当前这轮循环实际处理的元素数
```

### 8.3 `vstart`：异常与中断后的恢复位置

`vstart` 指定下一条向量指令从哪个元素索引开始执行。可恢复的异常或中断发生在向量指令执行中途时，硬件可将故障元素索引写入 `vstart`；恢复后，指令跳过先前已完成的 prestart 元素，从该元素继续执行。正常完成的向量指令会将 `vstart` 清零。

设计目的在于避免重复执行已经完成的元素。对可能访存、产生异常或具有副作用的向量操作，简单地从元素 0 重启可能导致重复访问或重复副作用；`vstart` 使指令级恢复仍能保持元素级精确语义。

### 8.4 `v0.mask[i]` 与 `vm`：按元素的条件执行

掩码向量指令使用 `v0.mask[i]` 作为元素 `i` 的谓词：该位为 1 时元素执行，为 0 时元素成为 inactive。指令编码中的 `vm` 位决定是否使用该掩码：`vm=1` 表示无掩码执行，`vm=0` 表示使用 `v0`。

设计目的有两点：

- 支持向量化后的条件分支、筛选、条件赋值和稀疏访问。
- 被关闭的访存元素不访问内存，也不会触发异常，从而允许安全地把标量条件控制转化为向量谓词。

RVV 将掩码存放在普通向量寄存器 `v0`，而不增加独立掩码寄存器文件，以减少架构状态。`v0` 仍是普通向量寄存器，只在掩码操作数位置按每元素 1 bit 解释。

### 8.5 `vta` 与 `vma`：无效位置的写回策略

`vta` 控制 tail 元素，`vma` 控制被掩码关闭的 inactive 元素：

| 字段 | 值 | 汇编标志 | 结果语义 | 设计原理 |
| --- | --- | --- | --- | --- |
| `vta` | 0 | `tu` | tail 保持旧值 | 后续确实需要 tail 数据时，保证旧值可用。 |
| `vta` | 1 | `ta` | tail 不可依赖 | 硬件可避免为无用 tail 读取和合并旧目的寄存器数据。 |
| `vma` | 0 | `mu` | inactive 元素保持旧值 | 后续确实需要被掩码关闭位置的数据时，保证旧值可用。 |
| `vma` | 1 | `ma` | inactive 元素不可依赖 | 硬件可避免合并无用旧值，特别有利于寄存器重命名和宽流水线。 |

`ta` 或 `ma` 不表示硬件一定写入随机值。规范允许硬件保留旧值或覆写全 1；正确的软件只能把这些位置视为不可用。`vma` 也不负责启用掩码，它只规定掩码已经关闭元素后的目的寄存器语义。

### 8.6 `vill`：不支持配置的可检测结果

`vill` 在 `vtype` 的最高位。若 `vset*` 请求了实现不支持的 `SEW`、`LMUL` 或其他 `vtype` 组合，规范的常规处理是置 `vill=1` 并将 `vl` 设为 0；随后执行依赖 `vtype` 的向量指令会触发非法指令异常。

设计目的不是让不支持的配置继续以未知方式执行，而是给软件提供可检测的能力边界。软件可检查 `vill` 并选择兼容路径，因此新代码不会在旧硬件上静默得到错误结果。

### 8.7 `vlenb`、`VLEN` 与 `ELEN`：硬件能力边界

| 名称 | 是否为运行时 CSR 字段 | 含义与设计作用 |
| --- | --- | --- |
| `VLEN` | 否 | 单个物理向量寄存器的位宽，是实现时固定的硬件资源大小。 |
| `vlenb` | 是 | `VLEN / 8`，让软件直接获得单寄存器字节数，用于上下文保存区和地址计算，且不扰动当前 `vl`、`vtype`。 |
| `ELEN` | 否 | 实现能够产生或消费的最大元素位宽，描述硬件支持的最大数据类型能力。 |

`VLEN` 固定而 `vl` 可变的组合，是 RVV 能同时做到硬件可扩展和软件可移植的原因：硬件通过更大 `VLEN` 提升单轮吞吐量，软件仍按 `vl` 驱动同一循环。

### 8.8 `vxrm`、`vxsat` 与 `vcsr`：定点数值状态

| 字段 | 含义 | 设计原理 |
| --- | --- | --- |
| `vxrm[1:0]` | 定点舍入模式：`rnu`、`rne`、`rdn`、`rod` | 定义缩窄、右移等定点操作的舍入规则，保证不同硬件执行同一程序时得到一致数值结果。 |
| `vxsat[0]` | 定点累计饱和标志 | 只用一个累计状态报告一批元素中是否出现过饱和，避免为每个元素额外保存 flag。软件可先清零、执行计算、再读取它。 |
| `vcsr` | `vxrm` 与 `vxsat` 的合并视图 | 提供同时保存、恢复或读取这两个定点状态的入口，同时保留独立 CSR 供单字段访问。 |

### 8.9 `mstatus.VS`：操作系统的向量上下文状态

`mstatus.VS` 是特权架构状态而非普通 RVV 用户 CSR，可表示 `Off`、`Initial`、`Clean` 或 `Dirty`。执行会改变向量状态的指令后，硬件将该状态标记为 `Dirty`；若为 `Off`，访问向量指令或向量 CSR 会触发非法指令异常。

设计目的在于降低上下文切换成本。向量寄存器组很大，操作系统不应在每次任务切换时无条件保存 `v0` 到 `v31` 及所有向量 CSR；只有 `VS=Dirty` 的任务才需要保存实际被修改的向量上下文。带虚拟化的系统还使用对应的 `vsstatus.VS` 管理客户机向量状态。

### 8.10 状态分层总结

```text
SEW / LMUL / EEW / EMUL：元素宽度和寄存器容量
vl / vstart             ：本轮处理范围和恢复位置
v0 / vm                 ：哪些元素执行
vta / vma               ：不产生有效结果的位置是否保留旧值
vill                    ：当前向量配置是否受支持
vxrm / vxsat / vcsr     ：定点数值语义和状态
vlenb / VLEN / ELEN     ：物理容量和硬件能力边界
mstatus.VS              ：操作系统是否需要保存向量上下文
```

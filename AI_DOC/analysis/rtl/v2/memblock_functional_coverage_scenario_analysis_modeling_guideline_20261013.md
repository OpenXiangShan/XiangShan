# V2 MemBlock 功能覆盖率场景分析与建模准则

## 1. 文档定位

本文记录本轮及后续 V2 MemBlock 功能覆盖率场景分析与建模的统一参考准则。

本文只规定分析入口、Scala 到 Verilog 的映射方法、覆盖率监测信号选择原则和分析输出要求，
不直接定义某个具体模块的 coverpoint、cross、bin，也不代表已经完成任何具体 RTL 场景核验。

## 2. 版本与源码范围

| 项目 | 路径或取值 |
|---|---|
| 目标版本 | V2 |
| 当前分支 | `mem_ut_uvm_v2` |
| Scala/Chisel 源码目录 | `src/main/scala/xiangshan/mem` |
| 生成 Verilog RTL 目录 | `build/rtl` |
| 功能语义分析入口 | Scala/Chisel 源码 |
| 最终覆盖率监测依据 | 当前工作区生成的 Verilog RTL |
| 文档创建日期 | 2026-10-13 |

## 3. 核心原则

### 3.1 场景逻辑优先从 Scala 分析

功能场景分析应首先阅读 `src/main/scala/xiangshan/mem` 下的 Scala/Chisel 源码，确认：

- 功能意图和模块职责；
- 请求、响应、握手和流水级关系；
- 状态机、队列、指针和表项状态变化；
- redirect、flush、replay、retry、exception 和 writeback 等控制条件；
- 同一场景涉及的优先级、互斥关系和时序边界；
- 参数、循环展开、`Vec`、`Bundle` 和生成条件对硬件结构的影响。

Scala/Chisel 源码用于回答“功能场景是什么”和“场景在什么逻辑条件下发生”。不得只根据
Verilog 信号名称猜测功能语义。

### 3.2 覆盖率模型必须落到 Verilog

具体功能覆盖率场景建模必须以 `build/rtl` 中当前生成的 Verilog RTL 为最终信号依据。

coverpoint、cross、时序事件、采样条件和必要的辅助状态必须使用仿真中真实存在且可访问的
Verilog 信号或由这些信号构成的可观测条件。不能因为 Scala 中存在某个字段、变量或中间条件，
就直接假设 Verilog 中仍保留同名信号。

### 3.3 必须执行 Scala 到 Verilog 的映射核验

从 Scala 场景逻辑得到关键条件后，必须在 Verilog 中逐项核验其实现形态。重点检查：

- 信号是否保留原名或经过层次化重命名；
- `Bundle`、`Vec` 或多端口结构是否被扁平化；
- 中间条件是否被内联、常量传播或逻辑优化；
- 一个 Scala 条件是否被拆分为多个 Verilog 信号；
- 多个 Scala 条件是否被合并为同一个 Verilog 组合逻辑；
- Scala 寄存器或流水级是否在 Verilog 中形成不同名称的寄存信号；
- 参数化分支是否导致当前 V2 配置中不存在对应硬件；
- 目标信号是否只存在于子模块内部，或者已经通过顶层接口间接反映。

映射时应结合模块层次、端口方向、位宽、赋值链、寄存级数、握手条件和上下游连接关系，
不能只依赖名字相似度。

### 3.4 直接映射失败时使用 Verilog 可观测条件重建

如果 Scala 中的关键条件在 Verilog 中已被合并、拆分、优化或无法直接定位，应依据 Scala 的
功能语义和 Verilog 的真实实现，使用以下方式建立等价监测条件：

1. 使用多个 Verilog 内部信号组合重建 Scala 条件。
2. 使用模块接口的 `valid`、`ready`、payload、状态和返回结果重建事件。
3. 对跨周期场景保存必要的 transaction token、owner、流水级标签或历史状态。
4. 通过可观测的请求、响应、状态转移和结果组合推导内部事件。
5. 无法建立严格等价关系时，明确标注为代理条件，不得描述为直接信号映射。

重建条件仍必须完全由 Verilog 中可访问的信号构成。Scala 条件只能作为语义依据，不能直接作为
SystemVerilog coverage model 的采样对象。

## 4. 建模工作流程

后续每个功能覆盖率场景按以下顺序分析：

1. **定义功能场景**：说明要覆盖的设计行为、场景边界和预期结果。
2. **定位 Scala 入口**：找到相关模块、函数、状态机、队列或赋值逻辑。
3. **展开 Scala 条件**：整理前置条件、核心事件、时序阶段、互斥条件和完成条件。
4. **定位生成模块**：确认对应的 Verilog 文件、实例层次和模块边界。
5. **追踪 Verilog 实现**：沿端口、组合赋值和寄存器更新找到真实硬件条件。
6. **建立信号映射**：记录直接映射、组合重建或接口代理关系。
7. **确定采样时机**：定义采样时钟沿、握手事件、流水延迟和有效窗口。
8. **设计覆盖对象**：形成 coverpoint、bin、cross 或时序场景建议。
9. **检查可达性与合法性**：区分正向功能、协议非法组合、当前配置裁剪和已知缺陷签名。
10. **记录证据与风险**：列出 Scala/Verilog 依据、未确认项和后续波形核验需求。

## 5. 信号映射分类

每个关键条件应归入以下类型之一：

| 类型 | 含义 | 建模要求 |
|---|---|---|
| 直接映射 | Scala 条件在 Verilog 中存在语义一致的单一信号 | 记录完整层次、信号名、位宽和有效条件 |
| 重命名映射 | Verilog 保留同一逻辑，但名称发生变化 | 通过赋值链、位宽和时序证明对应关系 |
| 展开映射 | Scala 的 `Vec`、`Bundle` 或循环生成逻辑被展开为多路信号 | 列出各 lane、slot、port 或字段的对应规则 |
| 组合重建 | Scala 条件需要由多个 Verilog 信号组合表达 | 给出组合表达式及每个子条件的来源 |
| 时序重建 | 场景需要跨周期历史状态或 transaction token 才能判断 | 定义 token 建立、推进、取消和释放条件 |
| 接口代理 | 内部条件不可直接观察，只能通过接口行为推导 | 说明代理条件与原条件的等价边界和误判风险 |
| 不可观测 | 当前 Verilog 中无法建立可靠直接或间接条件 | 暂不建立正向 bin，并记录需要的 bind、探针或 RTL 暴露需求 |

## 6. 覆盖率场景输出要求

每个具体场景的分析结果至少包含：

| 项目 | 内容要求 |
|---|---|
| 场景名称 | 使用能够表达功能行为的中文名称，保留必要的 RTL 术语 |
| 功能目标 | 说明该场景验证的设计能力或边界 |
| Scala 依据 | 列出文件、模块、函数或关键逻辑，并解释功能语义 |
| Verilog 依据 | 列出生成 RTL 文件、模块层次和真实信号 |
| 映射类型 | 标明直接映射、组合重建、时序重建或接口代理 |
| 前置条件 | 事务类型、状态、资源条件、配置和互斥限制 |
| 触发事件 | 明确 `valid`、`ready`、`fire`、状态转移或关键寄存事件 |
| 采样时机 | 明确同拍、下一拍、固定流水延迟或直到响应完成 |
| 预期结果 | 说明场景发生后应观察到的状态或接口结果 |
| 覆盖建议 | 给出 coverpoint、bin、cross 或时序覆盖维度 |
| 排除条件 | 标明非法协议、不可达组合、配置裁剪和不应计入 closure 的情况 |
| 可信度 | 标明已证明、强证据推导、接口代理或待波形核验 |

## 7. 采样与时序约束

1. Decoupled 接口事务通常只在 `valid && ready` 时认定为发生，除非源码明确规定
   valid-only sideband 语义。
2. 流水级场景必须确认条件属于哪一拍，不得把不同流水级的信号无条件组合采样。
3. 对跨周期请求与响应，coverage model 必须保存足以区分事务的 owner、ID、指针、索引、代次或
   其他 transaction token。
4. redirect、flush、cancel、replay 和 retry 需要明确事件生效周期及其影响范围，避免将迟到响应
   归属到新事务。
5. 没有独立 `valid` 的 payload、pointer 或状态字段只能在所属有效事件成立时采样。
6. 若 Verilog 优化使内部场景只能通过结果反推，必须同时采样必要的输入条件和输出结果，避免仅凭
   单个结果信号判断场景命中。

## 8. 可信度与结论边界

分析结论使用以下可信度标记：

- **已证明**：Scala 功能逻辑与 Verilog 实现均已定位，信号和时序关系完整闭合。
- **强证据推导**：没有单一直接信号，但 Verilog 组合或时序链能够完整重建场景。
- **接口代理**：内部状态不可见，通过接口请求、响应和结果建立代理覆盖。
- **待波形核验**：静态源码关系基本成立，但流水延迟、动态互斥或实例层次仍需仿真波形确认。
- **不可建模**：当前可见 Verilog 信号不足以可靠区分该场景。

接口代理或待波形核验的场景不得写成无条件确定的内部 RTL 事实。不可建模场景不得通过放宽条件
伪造覆盖命中。

## 9. 使用边界

- 本文适用于 V2 MemBlock 功能覆盖率场景分析和覆盖模型设计。
- 本文不授权修改 Scala、Verilog、UVM、脚本、filelist 或构建配置。
- 本文不替代具体模块的功能 flow、interface 分析或覆盖模型文档。
- 后续具体场景文档应引用本文，并继续以当时工作区中的 Scala 和生成 Verilog 为准。
- 如果重新生成 RTL、切换 commit 或改变配置，必须重新检查关键映射，不能沿用旧信号关系。

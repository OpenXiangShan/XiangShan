### 测试框架问题描述

四个 CSR scalar cfg 通过 `run_eda_regression.sh --plus-file` 从独立目录加载，设计上不会再合并
`seq/plus_cfg/default.cfg`。这些 cfg 显式打开主存范围和 PMA/PMP model，却遗漏关闭 L2TLB
level-weight；`plus.sv` 的默认值使 `MEMBLOCK_L2TLB_LEVEL_WEIGHT_EN=1`，最终与
`MEMBLOCK_MAIN_MEM_RANGES_EN=1` 构成 sequence 禁止的配置组合。四项真实 EDA smoke 均在
`0.000ns` 报 `SEQ_CSR_CFG: LEVEL_WEIGHT_EN requires MAIN_MEM_RANGES_EN=0`。

责任属于测试框架 cfg 集成，不属于 RTL 或 RM：失败发生在 sequence 配置合法性检查，DUT 尚未接收
事务。不能通过关闭 `MAIN_MEM_RANGES_EN` 绕过，因为 CSR scalar 场景需要真实主存范围和 PMA/PMP
模型共同提供访问属性。

### 测试框架修改方案

本问题不修改 RM 或 RTL。在四个 CSR scalar cfg 中显式加入
`MEMBLOCK_L2TLB_LEVEL_WEIGHT_EN=0`，保留 `MAIN_MEM_RANGES_EN=1` 和
`PMA_PMP_MODEL_EN=1`。同时扩展 plus-file dry-run 测试，对四个 cfg 固定断言这三个前置参数，防止后续

### 测试框架问题描述

VPN、s2xlate、entry generation 均匹配，却因 owner 未标记取消而进入 provenance fatal。若新 epoch
已创建 canonical owner，则会报无 replay 证明的 stale owner handle。

原始 Sv39 10-seed 在此版本全部 PASS，未覆盖该迟到时序。为验证静态发现，先只加入本 Bug 的定向
测试，以未修复生产代码重新编译，稳定获得 1/1 FAIL。测试经 split observer、LU1/PTW 绑定、exact
token 绑定建立 owner，随后走 anchored redirect wrapper，最后提交旧 completion；没有先行构造错误。

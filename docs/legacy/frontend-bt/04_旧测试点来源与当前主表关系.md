## 3. 迁移关系：保留、重构和明确未继承项

### 3.1 测试点字段

**保留的语义字段**

- 旧层级的 `SPEC`、一级至五级路径，迁移为主表的五级层级列；路径中的功能主题（复位、取指、重定向、异常、ITLB/PTW、PMP、IBuffer、BPU 等）仍是主要导航语义。
- 旧 `Condition`、`Checkpoint`、`Object` 的职责被保留，并在主表中作为可执行场景、正确性判据和观测对象继续反标。
- 旧测试点中关于场景边界、信号对象和优先级的内容被用于生成/审阅新表，但不是逐行复制承诺。当前主表来自另一份 `Frontend_testpoint_0525.xlsx` 导入/演进；没有生成脚本或一对一映射证据时，只能确认主题和字段职责相近，不能声称旧 568 行逐项迁移。

**已重构的部分**

- 新主表增加 `coverage`、`status`、`testcase`、`evidence`，把“测试点描述”接到真实 DUT 回归和 artifact 反标闭环；旧表没有这组生命周期字段。
- 旧 `NO.`（如 `001`）和 `C/D/E/F` 平面列被规范化为层级列和完整路径；编号不继承为 `TP_ID`。当前 `skills.md` 要求用完整层级路径加唯一 `Bin_ID`，而不是 CSV 行号。
- 新主表扩展、合并并改写了叶子场景，故旧 364/568 行不能与当前 1686 行按行号、数量或文本相等性互相覆盖。旧资料只能作为 provenance 和审阅输入。
- 旧 `优先级`、`分解方法` 没有被声明为当前主表的稳定键；若需要继续使用，必须重新在当前主表语境下审核。

### 3.2 覆盖字段与 Bin ID

**语义上可继承的内容**

- 旧 `Coverage_Group` 名称和早期 bin 语义提供了当前 registry 的设计线索，例如 `reset_boot_path`、`fetch_path_type`、`redirect_type`、`frontend_exception_type`、`itlb_result_type`、`ptw_resp_type`、`pmp_exec_type`、`ibuffer_state` 以及若干 cross group。
- 旧试点的 L0 场景（`BIN-001..014`）和 FTQ/ITLB/PTW/PMP/IBuffer 边界（`BIN-105..116`）在当前 registry 中仍可找到同号条目，表示语义连续性；仍须以当前 registry 的路径、sampler、DUT SHA 和 evidence 为准。

**已重构或扩展的内容**

- 旧 pilot 已包含早期的采样事件、观测对象和命中判据字段；当前 schema 在其基础上增加 `Coverpoint`、`Legacy_Bin_ID`，并由当前 runtime/evidence 生命周期把采样结果接入真实 DUT 闭环。旧 pilot 仍不能直接驱动当前 recorder。
- 旧 `BIN-101..104` 的 BPU 基本预测抽象已改成 V3 细分（当前例如 `BIN-225..243` 的 `bpu_v3_*` bins）；不要把旧编号当作当前同名 bin。
- 2026-07-23 的当前 registry 保留一处**有意的历史命名空间冲突 lineage**：旧 registry 中的 BPU 子预测器项与四个交叉场景都曾占用 `BIN-201..204`；重编号后 BPU 项使用 `BIN-244..247`，并分别以 `Legacy_Bin_ID=BIN-201..204` 保存来源，原四个交叉场景仍保留当前 `BIN-201..204`。`Legacy_Bin_ID` 是只读 provenance 元数据，不是当前反标键，不能清空或按编号直接消歧；必须结合来源、当前 `Bin_ID`、group、coverpoint、bin 和完整测试点路径解释。
- 当前 registry 有 **222 条数据记录**，远大于旧 34-bin 试点；新增的 V3 BPU 子预测器、边界、异常和交叉条目没有旧 ID，不应人为回填旧 ID。旧 `COV-xxx` 也没有作为当前 active 反标键继承。

## 4. 正确使用旧资料的场景

可以使用旧资料：

1. 追溯某个当前层级/场景的最初来源，解释为何存在某个 `Condition`、`Checkpoint`、观察信号或风险场景。
2. 审核迁移、合并、拆分和删改：先在旧资料中找历史语义，再在当前主表重新确认适用 DUT 版本、叶子边界和 checker。
3. 设计回归补洞或 bug 复现：把旧 bin/场景作为候选输入，重新映射到当前 registry 的 `Bin_ID`，重新运行真实 DUT 并生成当前版本 artifact。
4. 调查旧覆盖率结果或评审记录：只作为诊断/历史证据，并记录旧文件版本、来源路径和恢复 commit。

## 5. 禁止事项

- 不把旧 CSV/XLSX、旧 mapping 或旧 pilot 复制回 node031 的 `docs` 作为第二份 active 主表/registry；不创建平行 `frontend_bt_functional_coverage_pilot.csv`。
- 不把旧 `NO.`、CSV 行号、`COV-xxx` 或旧 `BIN-xxx` 直接当作当前 `TP_ID`/反标键；`Legacy_Bin_ID` 必须结合来源和当前完整字段人工复核，不能单独按编号匹配或清除。
- 不依据旧表文字或旧 bin 命中，直接把当前主表状态升级为 `HIT`/`CLOSED`；当前 `skills.md` 要求真实 DUT、版本签名、checker/trace 和 evidence 通过门禁。
- 不把旧 V2/V3 文档当作当前 RTL/spec 的事实源；当前代码、DUT SHA、canonical 主表、registry 和人工 review 优先。
- 不将旧 coverage 结果与当前 registry、sampler 或 DUT build 混合合并；版本不兼容的 artifact 只能作诊断证据。

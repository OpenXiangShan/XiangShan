## 3. 重点问题：预测器动态切换

### 3.1 现象与复现

在绑定设计 `ecc3c3c7f` 的全核版本上，程序等待 BPU SRAM 初始化后，通过真实 CSR 指令和真实 JALR 指令训练、切换：先写 `sbpctl=4`，再切换到 `sbpctl=1`。切换后合法执行路径出现 illegal instruction，DUT/NEMU 在异常状态处发生差分，DUT 的 `mepc=0x80000048`、`mcause=2`。

同布局下固定 `sbpctl=4` 和固定 `sbpctl=1` 的对照均到达 GOOD TRAP；动态切换在两个 seed 重复出现，归档中的独立复跑得到相同失败签名。独立 NEMU 运行同一输入程序通过。**失败发生在写 `sbpctl=0` 之前，不能简单概括为“全部关闭预测器导致”。**

最初 BT 直接在 SRAM 初始化前关闭预测器并二次 reset 的激励不符合或未证明符合真实启动时序，已撤回作为架构缺陷证据；上述结论依赖后续真实 CSR 的全核用例。

### 3.2 当前理解与设计讨论

波形显示，模式切换后旧预测相关状态仍参与选择，FTQ 取指范围出现结束位置落在新起始位置之前的情况；偏移回绕后 ICache 请求范围被扩大，异常指令进一步进入交付链路。该描述是当前证据支持的故障传播分析，**最终修复层次和各级责任需设计确认**。

请设计确认：动态切换与在飞预测的预期行为、uBTB/MainBTB 的有效信息是否需要随 enable 切换隔离、以及 FTQ/ICache 对非法范围是否还需要防护。修复后建议至少覆盖固定模式对照、真实 CSR 切换、不同训练历史和方向，并复核 BT 与全核的一致性。

该缺陷在归档设计版本上已复现，归档记录设计侧已确认存在；**未取得当前最新设计主线的独立重跑或修复后通过证据**。

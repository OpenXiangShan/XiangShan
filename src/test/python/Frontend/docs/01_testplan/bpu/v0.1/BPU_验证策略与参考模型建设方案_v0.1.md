# BPU 验证策略与参考模型建设方案

**文档版本**：V0.1  
**创建日期**：2026-10-15  
**适用对象**：香山昆明湖 V3 Frontend / BPU  
**验证层级**：BPU 专项验证与 Frontend Block Test (BT)  
**验证方法学**：规则确认、分层参考模型、灰盒性质检查与预测质量评估

## 一、背景与验证目标

当前 Frontend BT 通过行为级模型、接口检查及参考指令流验证前端。BPU 自主产生预测块，环境接收预测与取指结果，并通过后端模型提供解析、提交和重定向反馈。当前尚无独立的周期精确 BPU 预测器参考模型。

BPU 的设计资料以实现代码为主，验证需要从代码梳理结构、状态和更新过程，再由设计人员确认预期规则。直接按 RTL 的分支、索引和流水结构翻译模型，容易使实现与模型共享同一错误。参考模型建设因此需要同时解决规则依据、实现独立性和时序精度三个问题。

在 IFU 检查、后端解析及恢复机制正确工作的前提下，分支方向或目标预测偏差通常增加错误路径取指和流水恢复开销，主要影响性能。最终指令流正确反映了纠错后的执行路径；评价 BPU 本身还需要检查局部行为、内部状态及预测质量。

BPU 的训练身份、历史更新、队列控制和重定向恢复也会影响前端状态和取指推进。该类实现错误可能造成状态失配、恢复错误或停滞，需要作为功能风险验证。

本方案形成三类结论：一是已确认设计规则下的预测、训练和恢复行为是否正确；二是在约定程序和环境条件下预测质量是否满足基准；三是现有检查能证明的范围、剩余风险及周期精确模型的建设需求。

本文为待评审的建设方案。文中事件接口、检查器划分和阶段交付属于拟议设计；具体 RTL 信号、时序规则、性能阈值及工作量在代码梳理和设计评审后确定。

## 二、检查依据及独立性

### 2.1 检查依据的分工

| 依据 | 主要用途 | 适用范围与限制 |
| --- | --- | --- |
| RISC-V 语义与程序参考执行 | 确认实际分支类型、方向、目标及正确执行路径 | 提供预测质量统计的真实结果及最终指令流参考；具体预测策略由设计规则定义 |
| 设计确认的最小规则说明 | 定义预测器状态、更新、选择及恢复的期望行为 | 作为功能模型和性质检查的依据，逐条记录确认状态 |
| RTL 代码与仿真观测 | 梳理结构、观测接口、实际时序及问题线索 | 代码解释需与设计意图核对，观测值作为被检查对象 |
| 独立推导和人工小例子 | 验证计数器、历史、RAS 及身份关联等局部规则 | 适用于规则清楚、状态可控且可以手算的范围 |
| 认可的性能基准 | 评价固定条件下的准确率与恢复开销 | 记录设计版本、程序、预热和反馈时序，阈值需评审确认 |

### 2.2 从代码形成规则的工作方式

代码梳理首先记录“实现观察”：模块连接、状态含义、读写条件及先后关系。验证人员再从功能目标提出“期望规则”，列出推导依据、可能的其他解释及边界例子。设计人员确认后形成可执行规则，模型和检查器引用规则编号。

每条规则记录为“待确认、已确认、存在分歧或已修订”。待确认规则可以用于探索和定位，相关结果保留前提；正式通过结论引用已确认规则。代码变化与规则变化分别评审，避免实现修改后同步接受模型变化。

对缺少独立依据的索引、替换、仲裁和恢复细节，保留明确的评审问题。已有公开预测算法可以帮助理解和提出检查性质；采用的具体变体仍由本设计规则确认。

### 2.3 最小规则说明的内容

| 规则领域 | 需要确认的问题 | 形成的检查依据 |
| --- | --- | --- |
| 预测块语义 | 起始 PC、块范围、分支位置、方向、目标和有效位如何对应 | 预测块字段约束及身份关联规则 |
| 各级预测与选择 | 各预测器职责、默认结果、多级修正条件及结果优先级 | 局部预测模型和选择性质 |
| 表项与更新 | 索引、标签、计数器、分配替换、更新使能及饱和规则是什么 | 表项状态及更新期望 |
| 训练时机 | resolve、commit 及其他反馈分别触发哪些更新 | 事件来源及训练顺序规则 |
| 历史维护 | 投机历史、已提交历史、快照及恢复点如何维护 | 历史状态转换和恢复期望 |
| RAS | CALL/RET、压弹栈、溢出、下溢及回滚如何处理 | 栈操作模型和边界检查 |
| 同周期交互 | 预测与训练同址时读取哪个状态，多个更新如何排序 | 读写可见性、旁路及优先级规则 |
| 取消与复位 | override、redirect、flush 和 reset 如何影响预测与状态 | 取消范围、恢复顺序及初始化规则 |

### 2.4 规则记录示例

示例问题：同周期预测与训练访问同一计数器时，预测读取更新前的值，还是通过旁路读取更新后的值？

规则记录包含：规则编号、相关模块及信号、代码中的当前行为、两种行为对应的小例子、设计确认结果和确认版本。确认后，模型用独立状态转换描述期望，适配层关联实际预测与训练事件，定向用例触发同址读写并检查结果。

本例用于说明规则形成过程，具体取值和旁路行为待设计确认。

## 三、分层验证架构

### 3.1 各层职责与结论

| 验证层 | 输入与判定依据 | 输出结论 |
| --- | --- | --- |
| 程序与执行语义 | 程序字节、参考执行结果、实际有效交付指令 | 纠错后指令流的 PC、指令及顺序正确性 |
| 接口与状态性质 | 已确认规则、预测/训练/恢复事件及内部观测 | 字段约束、身份、握手、更新条件和恢复等局部行为正确性 |
| 分部件事件模型 | 明确排序的有效事件及独立维护的期望状态 | 计数器、RAS、历史及部分表项状态的演化正确性 |
| 预测质量评估 | 与真实执行结果关联的预测记录及固定基准 | 方向和目标准确率、错误分布及恢复开销 |
| 局部或整体时序模型 | 已确认流水规则、训练可见性和恢复优先级 | 评审范围内逐周期或逐预测块的精确一致性 |

这些层次共同提供证据。每项通过结论说明依赖的规则、使用的观测及可证明范围；尚无充分判定依据的内容保留为开放项。

### 3.2 模型与 RTL 之间的关系

程序及参考执行提供实际分支结果；设计确认的规则提供状态转换依据。模型根据两类依据及有效事件独立维护期望状态，RTL 监视器提供实际输出与状态，检查器负责关联和比较。

适配层处理信号读取、握手识别、事件身份及时间对齐。模型层表达预测算法和状态规则。对分支真实方向、目标及训练身份等可独立获得的信息，使用程序参考和身份关联检查；RTL 给出的训练字段同时作为被检查对象。

期望状态从已确认的初始化规则或受控状态装载建立。直接读取 DUT 当前状态建立快照时，记录该快照作为前提，并明确该次检查仅覆盖快照之后的演化。

## 四、事件级参考模型与时序精度

### 4.1 建议的事件信息

下列事件为模型接口建议。具体字段根据当前 RTL 可观测性和规则确认结果确定。

| 事件 | 建议信息 | 用途 |
| --- | --- | --- |
| 预测产生或被接受 | PC、预测序号、FTQ 身份、分支位置、方向、目标、预测来源及历史快照标识 | 记录每次预测及其形成时的上下文 |
| 分支解析 | 动态分支身份、实际类型/方向/目标、有效条件 | 关联真实结果、识别预测偏差 |
| 训练更新 | 被训练预测的身份、训练来源、目标表项、更新条件及有效时刻 | 检查训练对象和状态变化 |
| 历史/RAS 更新 | 对应指令或预测身份、操作及快照标识 | 推导投机状态及恢复期望 |
| 重定向与恢复 | 来源、优先级、恢复 PC、截断位置及恢复快照 | 检查取消范围与新路径状态 |
| 复位与配置变化 | 初始化范围、配置值及生效时刻 | 建立模型状态和运行条件 |

同一个 PC 在循环、重试及错误路径中可能出现多次。事件使用动态身份关联，包含必要的 FTQ 代次或等效请求身份，区分回绕和复用。

### 4.2 事件处理过程

预测事件到来时，模型基于此时应当可见的期望状态计算或记录结果，并保存后续训练及恢复所需的元信息。分支解析后，通过动态身份关联真实结果。训练事件依据已确认规则更新模型状态。重定向时，模型按恢复点修正投机历史、RAS 和有效预测记录。

实际接口可能区分“预测形成”“预测呈现”和“预测被接受”。这些时刻分别记录，按设计定义选择状态推进条件，处理反压期间的重复呈现。

### 4.3 精度逐步提高

第一阶段适合选择时序边界清楚的局部规则，以有效事件及明确顺序驱动模型。涉及同周期读写、多级 override、训练旁路或历史提前更新时，需要在对应局部补充周期、阶段及优先级信息。

当验证目标要求每周期、每预测块精确对照时，模型需要覆盖所有会影响该预测结果的状态与时序。可先建设局部精确模型，再根据缺口和收益决定扩展到完整 BPU。事件级建模同样依赖训练可见性与事件顺序的明确定义。

## 五、模型试点与性质检查

### 5.1 分部件模型候选

| 候选部件 | 独立表达方式 | 重点边界 |
| --- | --- | --- |
| 饱和计数器及更新 | 按确认的位宽和更新规则编写数学状态转换 | 最大/最小值、使能、同址并发和更新优先级 |
| RAS | 用独立栈结构维护期望返回地址及恢复快照 | 嵌套调用、栈满/空、压弹同时发生和回滚 |
| 分支/路径历史 | 用位序列及快照表达更新与恢复 | 更新数量、历史长度、投机与提交及多来源恢复 |
| 简单表项行为 | 用映射结构表达标签、有效位、分配和更新 | 同索引不同标签、冲突、替换及读写交互 |
| 多级结果选择 | 按已确认条件和优先级计算最终采用结果 | 同时有效、override、取消和级间关联 |

试点按规则清晰度、内部观测能力、场景可控性和预期收益选择。首个部件由设计与验证共同确定。

### 5.2 独立性质检查

| 检查类别 | 主要检查内容 |
| --- | --- |
| 预测字段约束 | 起始 PC、块边界、分支位置、有效位和目标满足确认的格式及语义 |
| 训练身份 | PC、分支类型、预测元信息、实际结果及 FTQ 身份属于同一次动态分支 |
| 状态更新 | 更新发生的条件、次数和内容符合规则；禁止更新的条件下状态保持 |
| 反压与接受 | 有效负载在约定条件下稳定，预测接受和状态推进次数正确 |
| 历史与 RAS 恢复 | 恢复点、快照和操作顺序正确，新路径使用期望状态 |
| 多级协同 | 各级预测关联到同一请求，修正和选择遵循约定优先级 |
| 取消与活性 | 被取消结果按规则退出，合法请求在约定前提下持续推进 |

活性检查给出外部响应、后端接收及公平性前提。超时阈值依据设计约束和环境条件确定，并保留停滞位置以便定位。

### 5.3 训练与恢复用例

定向程序集可包括固定方向分支、方向交替或周期模式、直接跳转、多个间接目标、嵌套 CALL/RET、历史相关分支及构造的索引冲突。程序布局、训练次数、预热窗口和控制事件均记录为用例参数。

对已确认规则的小状态场景，可以直接给出预测或状态期望。复杂训练序列用于激活机制和分析预测质量，其验收条件结合算法和资源约束确定。反复执行后的变化还可能受别名冲突、替换和多级预测交互影响。

### 5.4 受约束的关系检查

在模型初始状态相同、有效预测/训练/恢复事件顺序相同，且相关配置保持一致的前提下，可以对环境插入空闲周期等变体进行比较。比较前确认该变化对历史、训练可见性和周期相关机制的影响。

地址重排、训练时刻变化和预测器开关切换可能改变索引、冲突及多级选择，其结果按设计规则或性能实验解释。每项关系检查记录成立前提，避免将经验趋势写成普遍性质。

## 六、预测质量评估

### 6.1 真实结果与预测的关联

参考执行提供实际分支类型、方向和目标。统计前将预测记录、实际交付及后端解析关联到同一次动态分支，区分正确执行路径、投机错误路径和被取消预测。

预测记录需要保留预测时刻和最终采用的预测级别。初级预测及多级修正可以分别统计，并明确整体指标使用哪个观察点。训练流程和预测质量统计分别核对身份及有效条件，避免同一关联错误同时影响激励和判定。

### 6.2 指标口径

| 指标 | 建议定义 | 待确认内容 |
| --- | --- | --- |
| 方向预测准确率 | 方向正确的条件分支数 / 纳入统计的条件分支数 | 预测观察点、有效预测和缺失预测的计入方式 |
| 目标准确率 | 目标正确的事件数 / 纳入统计的目标预测事件数 | 条件跳转、直接跳转、间接跳转和返回的分类及分母 |
| 错预测频度 | 错预测事件数按约定有效指令数归一化 | 是否使用每千条指令、采用交付还是提交口径及去重规则 |
| 恢复开销 | 错预测被识别后至约定恢复事件的周期差 | 起止事件、外部反压及存储延迟的记录方式 |
| 分项诊断统计 | 按预测器来源、分支类型、训练阶段和冲突条件分类 | 各类结果的归属和多级修正计数方式 |

指标表给出口径建议，具体分母、统计窗口和验收阈值由设计与验证评审确定。

### 6.3 基准与环境条件

每次实验固定并记录 RTL 版本、设计参数、预测器使能、程序及地址布局、起始状态、预热长度、存储响应、后端反馈时序和随机种子。重复实验用于分析波动和稳定性，基准差异保留逐分支或分类型诊断。

已有认可版本可提供回归趋势基准；趋势一致仅覆盖该程序集及统计条件。其他预测器实现可辅助算法实验和敏感性分析，其参数、历史、流水及训练机制的差异需要单独解释。

Frontend BT 提供受控条件下的预测质量和恢复开销统计。CPU 的 IPC 及全核性能结合全核工作负载、后端执行和存储条件评估。

## 七、模型与检查器有效性验证

### 7.1 模型自身的独立检查

从规则构造可手算的小序列，明确每一步输入、期望状态和输出。模型测试包含初始化、边界、并发、恢复及身份复用，覆盖正向和拒绝行为。设计人员确认关键样例，复杂规则可采用另一种简化表达交叉核对。

模型实现避免复用 RTL 的更新函数、错误处理分支及待验证索引计算作为唯一依据。必须共享的配置参数单独管理；算法规则的来源、推导和确认记录随模型维护。

### 7.2 已知错误注入

| 注入错误 | 预期触发的检查 |
| --- | --- |
| 计数器更新方向反转或饱和边界偏移 | 局部状态模型及定向边界检查 |
| 错用另一条分支的训练身份 | 动态身份及训练关联检查 |
| 遗漏一次历史恢复或使用错误快照 | 历史模型及恢复后状态检查 |
| RAS 恢复位置偏移 | 栈模型及嵌套返回场景 |
| 多级结果选择优先级错误 | 选择性质及竞争定向用例 |
| 有效事件被漏采或重复采样 | 波形/独立采样对照及事件计数检查 |

错误注入优先在隔离测试构建或检查器输入流中实施。输入流注入验证检查器逻辑，RTL 注入进一步验证探针、适配和完整检测链路；两类结果分别记录。

已知错误被检出表明对应检测能力有效，其他算法和时序缺口继续单独评估。

### 7.3 仿真与采样可信度

选择复位、单周期脉冲、预测接受、训练并发及恢复等场景，在 Verilator 和 VCS 下对照。明确驱动阶段、时钟边沿及信号稳定后的采样时刻，将 Python 事件与波形和独立 SV 采样或断言核对。

记录工具在初始化、X 态、组合收敛和调度方面的差异。SV 功能覆盖的工具支持范围、采样与报告能力先行确认，再制定迁移范围和试点。相关风险及工作量评估纳入 Frontend BT 总体验证方案第六章。

## 八、阶段实施与交付

### 8.1 实施顺序

| 阶段 | 主要工作 | 交付与出口 |
| --- | --- | --- |
| P0 结构与规则梳理 | 阅读代码、整理状态与事件、提出歧义问题 | 结构及观测清单、规则初稿、设计确认问题清单 |
| P1 局部试点 | 确认首个部件规则，搭建事件适配和独立模型 | 可手算样例、定向场景、DUT 对照及错误注入记录 |
| P2 行为检查扩展 | 增加训练身份、历史/RAS 恢复、多级协同和边界场景 | 规则—场景—检查器对应表、模块及交互回归 |
| P3 质量评估 | 建立动态分支关联、固定程序集及统计口径 | 设计认可的指标和基准、分项报告及退化诊断 |
| P4 精确模型决策 | 评估未覆盖风险及逐周期判定需求 | 建模范围、收益、工作量、维护责任和项目排期 |

P0～P4 是本专项实施阶段编号。行为检查和性能统计可按依赖并行推进；阶段出口与责任分工先行确认，实际日期根据试点结果纳入项目计划。

### 8.2 分工建议

| 角色 | 建议职责 | 评审输出 |
| --- | --- | --- |
| BPU 设计人员 | 解释意图，确认算法、状态、时序及性能目标 | 规则确认、歧义结论及基准验收口径 |
| 验证负责人 | 组织方案与模型分层，管理覆盖范围及剩余风险 | 检查矩阵、试点选择、建设范围与排期 |
| 模型与检查实现人员 | 编写独立模型、性质及定向用例 | 模型检查、DUT 回归和错误注入结果 |
| 环境与统计人员 | 维护探针、事件适配、工具对照和预测质量统计 | 采样可信度、身份关联及可重放实验记录 |

以上按职责分工，可由现有团队兼任；具体人员及投入由项目评审确认。

### 8.3 周期精确模型的决策依据

评审结合三个方面决定建设范围：需要精确判定的预测与时序行为；现有局部模型、性质和性能统计留下的风险；新增模型的收益、实现工期及后续设计变化维护成本。

若立项，进一步列出建模的预测器、参数配置、流水阶段、训练可见性、历史/RAS 恢复、多级选择及初始化范围，并确定模型自身验证方法。对范围外机制记录检查方式和剩余风险。

工作量估算在局部试点后给出，分别计入规则确认、模型实现、探针适配、时序调试、错误注入、双工具回归及变更维护。

## 九、证据与验收

每个功能结论记录规则版本、适用配置、场景、事件及内部观测、检查结果和失败定位信息。每个性能结论记录指标定义、分母、基准、环境条件及统计结果。

| 验收对象 | 验收要求 |
| --- | --- |
| 规则 | 意图有设计确认，歧义及适用范围有记录 |
| 局部模型 | 独立状态表达、手算序列、边界与恢复检查通过 |
| DUT 检查 | 目标事件发生，身份及采样可信，实际行为满足规则 |
| 检查有效性 | 对应已知错误能够触发预期失败，检测链路可定位 |
| 预测质量 | 在认可的程序、条件和指标口径下满足评审基准 |
| 剩余风险 | 明确尚未精确判定的机制、现有替代检查及后续计划 |

试点验收使用上述要求中适用的部分，逐项说明范围。最终通过结论区分端到端指令流、BPU 局部行为、预测质量及逐周期一致性。
